# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

All `dotnet` commands must be run from the `./src` directory. The tests need the specification submodule; after cloning run `git submodule update --init` (CI checks it out with `submodules: true`).

```bash
dotnet restore
dotnet build --no-restore -warnaserror
dotnet format --verify-no-changes          # check code style (CI enforces this)
dotnet format                              # auto-fix code style
dotnet test --no-build --verbosity normal  # run tests
dotnet pack --configuration Release -p:Version=<version> --output .
```

CI additionally passes `-p:AssemblyVersion` (pinned to the major) and `-p:FileVersion`; see `.github/workflows/publish-nuget.yml`.

## Architecture

This is a **JSON serialization library** for PureQL query models. It depends on `PureQL.CSharp.Model` (which mirrors PureQL specification `0.1.0-preview.2.0.1`; see its CLAUDE.md for the naming rules) and adds `System.Text.Json` support on top.

**Entry point:** `PureQLConverters` — a `sealed record` that implements `IEnumerable<JsonConverter>` and yields one `PureQLConverter<T>` per model type. Consumers register all converters into a `JsonSerializerOptions` instance in a single loop.

**Engine (project root, hand-written):** `ModelRegistry` holds a `ModelDescriptor` per model type and is built once. A converter buffers the value as a `JsonDocument` and asks the registry to read it.
- `RecordDescriptor` — a record as one JSON object, read through `ObjectReader` (tracks read properties, so any other one is rejected; `Many` / `OptionalMany` take the schema's `minItems`: 2 for operator operands, 1 for query lists) and written through `ObjectWriter` (omits schema defaults).
- `UnionDescriptor` — a OneOf union whose cases accept disjoint *signatures* (`Discriminators.Of`): the `operator` plus the declared `type` (`add decimal?`), or a leaf kind plus type such as `field decimal?` (a select item or group key has the type of its `expression`). The dispatch table is computed when the registry is built and throws on ambiguity.
- `ProbeUnionDescriptor` — `Equal*`, `NotEqual*`, `In*` and the other comparisons, chosen by the `TypeFamily` of the type that `Discriminators.Probe` reads from the operand (`integer` and `decimal` are one family).
- `PresenceUnionDescriptor` — query forms by `groupBy`, then `aggregate`; `From` / `Join` by `subquery`.
- `Literals/LiteralValues` — literal formats checked against the schema patterns (one spelling per value); values the schema or the CLR type cannot hold exactly are rejected on read and on write.

**Registrations:** `QueryRegistrations` (root types) is hand-written. The other `*Registrations` classes, in folders mirroring the model namespaces (`Fields/`, `Parameters/`, `Literals/`, `Keys/`, `Lists/`, `RowExpressions/`, `ProjectionExpressions/`, `GroupExpressions/`, `TotalExpressions/`, `GroupKeys/`, `SelectItems/`), were generated by a one-off script that reflects over the model: one registration per model type, the operator name and declared `IType` of each operator record from its name (`AddDecimalNullableRow` is `add` declaring `decimal?`; comparisons declare `boolean`, `count` `integer`), the cases of each union from its OneOf arguments, JSON property names equal to constructor parameter names, the schema's `minItems` for each list, and `over` read only in group context. Apply small model changes by hand in the same shape.

**Test project:** `PureQL.CSharp.Model.Serialization.Tests` targets `net10.0` and uses xunit. The fixtures come from the git submodule `src/Tests/PureQL-Specification`, pinned to spec tag `0.1.0-preview.2.0.1` and copied to `Specification/` in the test output: `samples/`, `tests/valid/`, `tests/invalid/` and the schema. To move to a new spec version, check out its tag in the submodule together with the matching model bump. Valid fixtures must round-trip to semantically equal JSON (`JsonSemantics`: sorted keys, numbers by value, everything else as text, as every value has one spelling); invalid ones must fail, except those listed in `InvalidQueryTests.AcceptedByModel` (constraints the model cannot express). `ProbeTests` checks that `Discriminators.Probe` reports the family of the declared type. `ModelRoundTripTests` builds every variant of every model type by reflection (`ModelSamples`: operands of a nullable operator are nullable, those of a non-null one are not, so the declared type is exact) and checks it reads back as the same variant. `MinItemsTests` cuts every list of those variants below and to its `minItems` (checked against the schema) and expects a rejection and an acceptance. `SchemaConformanceTests` validates the JSON written for each of those variants against the schema definition its type mirrors (JsonSchema.Net), so written JSON is checked against the specification, not only against the reader.

**Multi-targeting:** net7.0, net8.0, net9.0, net10.0. `IsAotCompatible` is `true` for net8.0 and later (the analyzers do not support net7.0); no reflection or `JsonSerializer` calls inside converters.

**Publishing:** triggered by pushing a semver tag (pattern `*.*.*`). The tag becomes the `PackageVersion`. The workflow publishes to both GitHub Packages and NuGet.org.

## Code Style

Enforced via `.editorconfig` and `dotnet format --verify-no-changes` in CI:

- No `var` — always use explicit types
- No expression-bodied methods or constructors — use block bodies
- Expression-bodied properties and accessors are required
- File-scoped namespace declarations (`namespace Foo.Bar;`)
- Private fields prefixed with `_` in camelCase (e.g., `_options`)
- Braces always required, even for single-statement blocks
- Max line length: 90 characters
- Allman brace style — opening brace on its own line for all blocks
- `System.*` using directives sorted first, no blank line between using groups
- Parentheses required in arithmetic and relational binary operators for clarity
